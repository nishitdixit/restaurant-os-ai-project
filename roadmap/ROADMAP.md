# Product Roadmap

## Phase 0 — Foundations

Outcome: repository, architecture, CI/CD, tenant-safe core and design system foundations exist.

Deliverables:

- project scaffold;
- auth and tenant context;
- database/migrations;
- base UI system;
- API conventions;
- observability;
- test harness;
- deployment pipeline.

## Phase 1 — Pilot MVP

Outcome: one restaurant can run a real direct-order workflow.

Capabilities:

- onboarding;
- storefront;
- catalog;
- availability;
- cart;
- checkout;
- payment;
- order lifecycle;
- basic notifications;
- delivery zone;
- manual dispatch;
- customers;
- offers;
- analytics;
- SEO foundation.

## Phase 2 — Operational V1

Outcome: restaurant uses the platform daily without constant developer support.

Capabilities:

- better order board;
- kitchen display;
- richer stock controls;
- customer segmentation;
- WhatsApp campaigns;
- reordering;
- referral/loyalty basics;
- delivery provider adapter;
- richer reports;
- onboarding improvements.

## Phase 3 — Multi-tenant growth

Outcome: several independent restaurants can onboard and pay.

Capabilities:

- tenant self-service;
- billing/subscriptions;
- custom domain;
- tenant usage limits;
- onboarding templates;
- support tooling;
- tenant-level analytics;
- stronger integration framework.

## Phase 4 — Restaurant OS

Outcome: deeper operations and retention.

Capabilities:

- inventory ledger;
- recipes/BOM;
- procurement basics;
- multi-outlet;
- multi-brand;
- aggregator sync where supported;
- automated delivery orchestration;
- advanced CRM;
- margin analytics.

## Phase 5 — AI layer

Outcome: system recommends and explains actions using trusted business data.

Capabilities:

- AI analyst;
- campaign assistant;
- demand forecasting;
- anomaly detection;
- support copilot;
- operational recommendations.

## Sequencing rule

Do not move to the next phase simply because the previous phase is feature-complete. Move when the business outcome of the current phase is proven.
